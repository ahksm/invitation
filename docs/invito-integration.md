# Invito: подключение дизайна к платформе

Рабочая спецификация: как прототип Invito из Claude Design (`web/`) превращается в настоящий продукт поверх существующего бэкенда (`src/`). Её читают все, кто меняет фронтенд или API. Контракт API в разделе 3 общий для фронтенда и бэкенда: менять его можно только вместе с этим файлом.

## 0. Общие правила

- Стек: Node 22, TypeScript (ESM, NodeNext), Fastify 5, Drizzle 0.45 + node-postgres, Redis (ioredis), zod 4, grammY, vitest 5. Комментарии и сообщения об ошибках в коде пишутся по-русски, как в остальном проекте. Сообщения `HttpError` служат ключами перевода в `src/i18n.ts`: для каждого нового сообщения добавить переводы uz, uzc, en.
- Секреты никогда не коммитятся. `.env` в `.gitignore`. Репозиторий публичный.
- Миграции: менять `src/db/schema.ts`, затем `npm run db:generate` (drizzle-kit), сгенерированные файлы в `drizzle/` коммитятся.
- Проверки перед коммитом: `npx tsc --noEmit` и `npx vitest run`. Тесты используют `TEST_DATABASE_URL` и `TEST_REDIS_URL`.
- Деньги в тийинах (1 сум = 100), как сейчас.
- Часовой пояс событий: Asia/Tashkent (UTC+5, без перехода на летнее время). `data.date` + `data.time` в приглашении это местное время Ташкента.
- Языки (Locale): `ru`, `uz` (латиница), `uzc` (узбекский, кириллица), `en`. Бэкенд сейчас знает `ru|uz|en`: добавить `uzc` везде (users.locale, invitations.language, i18n, SMS, бот). Тексты `uzc` получаются из `uz` функцией `toCyr` из `web/invito-data.js` (единый источник; баг с «yo‘» → «йў» исправить в самом `toCyr`).

## 1. Исходники дизайна (`web/`)

- `web/Invito.dc.html`: всё приложение (разметка в `<x-dc>`, логика в `<script type="text/x-dc" data-dc-script>`).
- `web/InviteCover.dc.html`: обложка шаблона.
- `web/invito-data.js`: словари (ru/en/uz/uzc), 12 событий, 14 стилей, палитры, 60 шаблонов, утилиты (`slugify`, `toCyr`, `derive`). Демоданные `GUESTS`/`CONTACTS` используются только в демо-режиме тура.
- `web/invito-engine.js`: музыка, рендер OG/stories-картинок, скретч-карта.
- `web/support.js`: оригинальный рантайм `.dc.html`. Руками не правится: при отдаче сервер накладывает на него патчи (раздел 2).
- `web/invito-api.js` (новый): ES-модуль с клиентом API и помощниками (загрузка файлов, сжатие картинок, QR). Логика Invito подгружает его так же, как `invito-data.js`.
- `web/DESIGN.md`, `web/github.md`: заметки дизайна.

Бэкенд импортирует `web/invito-data.js` во время выполнения (динамический `import()` по абсолютному URL от `import.meta.url`), чтобы брать каталог шаблонов, стили со шрифтами, секции, треки и `toCyr` из одного источника. Типы описать вручную в `src/design-data.ts`.

## 2. Отдача фронтенда (`src/web/`)

Цель: дизайн работает как есть, но без `unsafe-eval`, без CDN и без двойной загрузки страницы.

1. Сборка в памяти при старте (в development пересобирать, если изменилось время файлов в `web/`):
   - `/app/dc-bundle.js`: классический скрипт.
     ```js
     window.__dcSources = { Invito: { template: "<сырой текст внутри <x-dc>>", props: {...data-props} }, InviteCover: {...} };
     window.__dcLogic = { Invito: function (DCLogic, StreamableLogic, React) { /* текст логики */ ; return Component; }, InviteCover: ... };
     ```
   - `/app/support.js`: `web/support.js` с патчами (каждый патч ищет точный фрагмент и падает при старте, если фрагмент не найден):
     1. логика берётся из `window.__dcLogic[name]`, `new Function` не вызывается;
     2. корневой шаблон и пропсы берутся из `window.__dcSources` и проходят тот же путь разбора, что и сырой текст (`parseDcText`/`encodeCase`), без `fetch(location.href)`;
     3. вложенные DC (`InviteCover`) берутся из `__dcSources`, без `fetch`;
     4. React не грузится с unpkg (его подключает оболочка);
     5. убрать `postMessage` в `window.parent` и обработчик `message` без проверки источника.
   - Хэш содержимого в `?v=` для кэша; ответы с `Cache-Control: public, max-age=31536000, immutable` при наличии `v`.
2. Статика: `/app/invito-data.js`, `/app/invito-engine.js`, `/app/invito-api.js` из `web/` (MIME `text/javascript`); `/app/vendor/react.production.min.js` и `/app/vendor/react-dom.production.min.js` из `node_modules/react@18.3.1/umd` и `react-dom@18.3.1/umd` (добавить зависимости); `/app/vendor/qrcode.js` из пакета `qrcode-generator` (глобальная функция `qrcode`).
3. Оболочка HTML (одна функция, разные данные):
   - `GET /`, `GET /app`, `GET /app/*`: приложение. Загрузочные данные `{ "mode": "app" }`.
   - `GET /i/:slug`: общая ссылка. Загрузочные данные `{ "mode": "shared", "slug", "view"? , "locked"? }` (view из раздела 3.6, при пароле только `locked` с `look`; `lang` страницы — `look.language`). Если попытки пароля из `?code=` исчерпаны, страница та же со статусом 429 и `locked.limited: true` (форма пишет «слишком много попыток», а не «неверный пароль»).
   - `GET /g/:token`: личная ссылка. `{ "mode": "personal", "token", "view" }`.
   - Неизвестное приглашение: оболочка с `{ "mode": "notfound" }` и HTTP 404.
   - В `<head>`: charset, viewport (`viewport-fit=cover`), `<title>` и `description` (у приложения — `DEFAULT_META` в `src/web/pages.ts`: что такое Invito, тем же языком, что первый экран главной), значки сайта (`/favicon.ico` 16/32/48 px, `/favicon.svg`, `/apple-touch-icon.png` 180 px — файлы в `public/`, их отдаёт `@fastify/static`; `/favicon.ico` браузер просит и без ссылки, поэтому 404 нет), OG-теги (`og:type`, `og:url`, `og:title` = names + « — » + длинная дата на языке приглашения, `og:description` = message до 160 символов, `og:image` = абсолютный URL `ogImageUrl` или обложки, `twitter:card=summary_large_image`), Google Fonts (тот же URL, что в `<helmet>` дизайна), `https://telegram.org/js/telegram-web-app.js` (статически, до рантайма), React, ReactDOM, qrcode, `dc-bundle.js`, `support.js`.
   - Загрузочные данные: `<script type="application/json" id="invito-boot">` с экранированием `<` как `<`.
   - Из `<helmet>` в `Invito.dc.html` убрать `<script src="telegram-web-app.js">` (теперь в оболочке). Динамический импорт модулей в логике заменить на абсолютные пути `/app/invito-data.js` и т.д. (страницы `/i/…` и `/g/…` иначе ищут модули не там).
4. CSP и заголовки:

   - `style-src 'self' 'unsafe-inline' https://fonts.googleapis.com`; `font-src 'self' https://fonts.gstatic.com data:`;
   - `img-src 'self' data: blob: https://images.unsplash.com`; `media-src 'self' blob: data:`;
   - `frame-src https://maps.google.com https://www.google.com https://oauth.telegram.org`;
   - `connect-src 'self'`;
   - `frame-ancestors 'self' https://web.telegram.org https://*.telegram.org` для `/`, `/app*`, `/i/*`, `/g/*`, `/oferta`, `/privacy`, `/contacts` и HTML-страницы «не найдено» на любом другом адресе; без `X-Frame-Options` на этих путях (иначе мини-апп не открывается в Telegram Web). Админка, API и JSON-ответы 404 остаются `frame-ancestors 'none'` и `X-Frame-Options: DENY`.
5. Старые страницы `public/app/` и `public/invite/` удалить. `public/admin/` и `public/shared/` (их использует админка) и значки сайта в корне `public/` остаются.
6. Dockerfile копирует `web/`. CI собирает и проверяет как раньше.
7. Юридические страницы (их требует Multicard для боевого режима): `GET /oferta` (публичная оферта), `GET /privacy` (политика конфиденциальности), `GET /contacts` (контакты и реквизиты). Код в `src/web/legal.ts`, тексты в `src/web/legal-texts.ts`.
   - HTML собирает сервер, без скриптов и без оболочки приложения; стиль Invito (Cormorant Garamond, Onest, JetBrains Mono, акцент `#d4452a`, светлая и тёмная тема по настройке системы), шрифты из Google Fonts. На телефоне оглавление свёрнуто (`<details>`), на широком экране — сбоку.
   - Язык: `?lang=ru|uz|uzc|en` (разбор как `pickLocale`: `uz-Cyrl` → `uzc`); без параметра, с неизвестным или повторённым — русский. Тексты `uzc` получаются из `uz` через `toCyr`; названия сервисов (Multicard, Eskiz, Telegram, Google…), подстановки и адреса ссылок не транслитерируются. Переключатель языка и ссылки между документами сохраняют язык; в `<head>` — `<title>` «<документ> — APP_NAME», `description`, canonical и `<link rel="alternate" hreflang>` на все четыре языка.
   - Реквизиты берутся из настройки `legal` (раздел 3.10). Выводятся только заполненные поля, плейсхолдеров нет. Без `companyName` исполнителем названа «администрация сайта <host из APP_URL>». В реквизитах и контактах всегда есть сайт, а Telegram-бот — если он запущен (`botUsername`).
   - Заголовки как у страниц приложения (`appHelmet`: CSP раздела 2.4, frame-ancestors с Telegram, без X-Frame-Options), `Cache-Control: private, no-cache` (сохранённые в админке реквизиты видны сразу), страницы индексируются.
   - Ссылки из приложения (подвал главной, строка согласия в листе оплаты): `/oferta`, `/privacy`, `/contacts`, для языка интерфейса кроме русского — с `?lang=<код>`.
   - Дата редакции на страницах — `LEGAL_REVISION`: при изменении текстов оферты или политики её нужно обновить.

## 3. Контракт API

Все ответы JSON. Ошибки: `{ "error": "<переведённый текст>" }` с кодом. Даты в ISO.

### 3.1 Общая конфигурация и сессия

- `GET /api/auth/config` → `{ telegram: boolean, botUsername: string|null, appUrl: string, prices: { sharedTemplate, seat, subscriptionMonth }, currency: "UZS", ai: boolean }`.
- `GET /api/auth/me` → `{ user: { id, phone, firstName, lastName, username, telegramId: string|null, locale, isAdmin, freeAccess }, access: { free, subscribed, subscriptionEndsAt: string|null }, prices, currency }`. 401 без сессии, 428 без телефона (как сейчас).
- `PATCH /api/auth/me` `{ locale?, firstName?, lastName? }`: язык интерфейса (и `uzc`) и имя в профиле, хотя бы одно поле (иначе 400 «Неверные данные»). Имя и фамилия обрезаются по краям, до 64 символов, без переносов строк и управляющих символов (400 «Имя и фамилия: до 64 символов, без переносов строк»); пустое имя — 400 «Введите имя». `lastName: ""` или `null` стирает фамилию. Только `lastName` у аккаунта без имени (вход по SMS) — 400 «Введите имя». Ответ — сохранённые поля: `{ ok: true, locale?, firstName?, lastName? }` (при смене имени — оба поля). Имя, изменённое здесь, отмечается в `users.name_edited`: вход через Telegram (`/webapp`, бот) и объединение с Telegram-аккаунтом его больше не перезаписывают (неизменённое имя по-прежнему обновляется из Telegram).
- `POST /api/auth/handoff` (нужна сессия, лимит 10 в минуту) → `{ url }`: одноразовая ссылка входа `APP_URL/api/auth/link?code=…` для этой сессии (5 минут, срабатывает один раз, как `/login` в боте). Мини-апп открывает по ней админку во внешнем браузере (`openLink`), куда его сессия иначе не попадает: `/link` ставит cookie и ведёт админа в `/admin/`, остальных — в `/app/`.
- Маршруты входа: `/telegram/start`, `/telegram/poll`, `/webapp`, `/phone/request`, `/phone/verify`, `/link`, `/logout`. Каждый успешный вход ставит cookie сессии (`session`, `HttpOnly`, `SameSite=Lax`, 30 дней).
- `POST /api/auth/webapp` при успехе отвечает `{ status: "ok", redirect, token }`. В Telegram Web мини-апп открыт во фрейме `web.telegram.org`, и cookie с `SameSite=Lax` туда не доходит, поэтому мини-апп хранит `token` в памяти и шлёт его во всех запросах к API заголовком `Authorization: Bearer <token>`. Сервер принимает и cookie, и заголовок.
- `POST /api/auth/webapp`, пока у пользователя нет телефона: `{ status: "phone_required", error?: string }`. `error` (на языке `X-Lang`) есть, если бот отклонил последний контакт этого Telegram: номер уже привязан к другому Telegram-аккаунту, прислан чужой контакт или номер не распознан. Новый контакт в боте причину сбрасывает (принят — следующий ответ `ok`, отклонён — новая причина). Причина хранится сутки.
- Лимит `POST /api/auth/webapp` — 40 запросов в минуту на IP, `POST /api/auth/telegram/start` — 30 (лист входа берёт ссылку на бота заранее, при открытии; за одним IP мобильного оператора много людей), остальные маршруты входа — 10: пока ответ `phone_required`, мини-апп опрашивает его не чаще раза в 3 секунды, а при 429 ждёт 5 секунд и продолжает.
- Токен в ответе других входов: `POST /api/auth/phone/verify` `{ phone, code, bearer? }` и `POST /api/auth/telegram/poll` `{ nonce, bearer? }`. С `bearer: true` успешный ответ содержит и `token` — тот же JWT, что в cookie: `{ status: "ok", redirect, token }`. Фронтенд шлёт `bearer: true` только в настоящем Telegram (`tgReal`), где cookie во фрейм `web.telegram.org` не доходит. На обычном сайте флаг не шлётся, и токен в ответе не появляется (скриптам страницы он не виден). `bearer` не boolean — 400.
- Вход через Telegram на сайте: `POST /api/auth/telegram/start` → `{ nonce, url: "https://t.me/<бот>?start=auth_<nonce>", ttl }` и cookie `tglogin` (секрет этого браузера, путь `/api/auth/telegram`, 5 минут). Затем `POST /api/auth/telegram/poll` `{ nonce, bearer? }` раз в 2 секунды → `{ status: "pending" }`, `{ status: "expired" }` (истёк, чужой браузер или уже забран), `{ status: "ok", redirect, token? }` или `{ status: "conflict", error }` (ниже). Ответ `ok` и `conflict` выдаётся один раз.
- «Подключить Telegram» из аккаунта — те же `start` и `poll`. Если `start` вызван с действующей сессией (cookie или `Authorization: Bearer`; пользователь с телефоном и не заблокирован), запрос запоминает этого пользователя. Подключается только Telegram, который подтвердил номер этого аккаунта собственным контактом в боте (кнопка «Поделиться номером»; бот принимает только свой контакт: `contact.user_id` — сам отправитель). Номер контакта Telegram присылает в международном виде, поэтому узбекский номер из контакта — только `998` и 9 цифр: девять цифр не считаются номером без +998 (короткий номер другой страны, например +508 55 12 34, не подтверждает +998 50 855-12-34 — ни для подключения, ни для обычного входа). Ссылка `t.me/<бот>?start=auth_<nonce>`, попавшая к другому человеку (пересланная, увиденная на чужом экране), его Telegram к аккаунту не подключит, и войти им в этот аккаунт нельзя.
  - Telegram без номера: бот, как при обычном входе, запоминает запрос (пока он действует) и просит поделиться номером; номер аккаунта он до этого не показывает. Контакт обрабатывается как обычно: номер аккаунта объединяет Telegram с аккаунтом (данные записи без номера — её создал бот или админ выдачей доступа по Telegram ID — и бесплатный доступ переходят к аккаунту), и запрос продолжается подтверждением (ниже). Другой номер привязывается к самому Telegram (его отдельный аккаунт или аккаунт с этим номером), а запрос сразу завершается отказом: `poll` отвечает `{ status: "conflict", error }` с «Номер этого Telegram отличается от номера аккаунта: подключите Telegram с тем же номером» (на языке `X-Lang`), бот пишет ту же причину, кнопки «Подключить» нет. Контакт, который бот не принял, потому что номер уже у другого Telegram, тоже сразу завершает запрос отказом с этой причиной («Этот номер уже привязан к другому Telegram-аккаунту»); чужой контакт или нераспознанный номер — нет, можно прислать свой.
  - Telegram этого аккаунта (после контакта с тем же номером или подключённый раньше): бот предлагает «Подключить этот Telegram к аккаунту +998 90 ***-**-67?» (номер аккаунта со скрытой серединой и устройство). После нажатия `poll` отвечает `ok` для этого же пользователя, событие `telegram_linked` в журнале (`login` не пишется).
  - Telegram, у которого номер уже есть, — другой аккаунт (номер не совпадает с номером аккаунта): после нажатия `poll` отвечает `{ status: "conflict", error }` («Этот Telegram уже привязан к другому аккаунту»), бот пишет ту же причину.
  При отказе ничего не привязывается, не объединяется с аккаунтом и не переключается: сессия не выдаётся и не меняется. Запрос подключения завершается входом только в аккаунт, из которого он начат (это проверяется и при завершении запроса, `settleTelegramLogin`): браузер, начавший «Подключить Telegram», не попадает в чужой аккаунт, даже если на этот `nonce` попало подтверждение обычного входа. Повторное нажатие кнопки или повтор ссылки после ответа ничего не делает. Telegram аккаунта не заменяется: у аккаунта с Telegram кнопки «Подключить Telegram» нет, а контакт с номером аккаунта из другого Telegram бот отклоняет (отказ выше).
  Без сессии (или с недействительной) `start` — обычный вход: `poll` выдаёт сессию аккаунта, которому принадлежит Telegram.
  Во фрейме Telegram Web cookie `tglogin` не сохраняется, поэтому запрос подключения забирает и та же сессия (cookie или `Authorization: Bearer` того пользователя, из чьего аккаунта начат `start`); сессия другого аккаунта получает `expired`. Обычный вход (без сессии при `start`) по-прежнему забирается только с cookie `tglogin`.

### 3.2 Содержимое приглашения (`InvContent`, колонка `invitations.data`)

zod-схема (лишние ключи отбрасываются):

| Поле | Тип и ограничения |
| --- | --- |
| names, host | строка ≤ 200 |
| message | ≤ 3000 |
| venue | ≤ 200 |
| address, contact | ≤ 300 |
| dress, secret | ≤ 500 |
| gifts, notes | ≤ 1000 |
| dressColors | массив `#rrggbb`, не больше 6 |
| program | массив не больше 8 из `{ time: "HH:MM" или "", title ≤ 120, place ≤ 200, address ≤ 300 }`; `address` необязателен (по умолчанию `""`, старые пункты читаются с `""`) |

| time | `HH:MM` или `""` (время стёрто) |

| font | строка ≤ 60; если шрифта нет у стиля шаблона, сервер подставляет первый шрифт стиля |
| palette | целое 0..2 |
| music | один из `TRACKS` или `custom` |
| intro | `envelope|curtain|scratch|none` |
| mapMode | `drawn|real` |
| motion | `still|zoom|video` |
| sections | массив `{ k: одна из SECTIONS, on: boolean }`; сервер убирает повторы и дописывает недостающие секции в конец с `on: false` |

Программа и маршрут: пункт с `place` — остановка маршрута на странице гостя. На рисованной карте отметки расставляются по числу мест (одна на место, повторное место — та же отметка); остановка с названием главного места (`venue`) — это его отметка «●», иначе место встаёт в маршрут по `time`. `address` — адрес остановки или ссылка на карту. Ссылкой страница гостя делает только `https://` адрес картографического сайта (первая такая ссылка в поле): `yandex.*` (uz, ru, com, kz, kg, by, ua, az, tj, tm, com.tr), `maps.app.goo.gl`, `goo.gl/maps`, `google.*/maps` и `maps.google.*` (com, co.uz, ru, kz, kg, by, com.ua, az, tj, tm, com.tr), `2gis.*` (uz, ru, com, kz, kg, ae); без логина, пароля и порта в адресе (`mapLink` в `web/invito-engine.js`). Остальные ссылки (`http:`, `javascript:`, `data:`, другие сайты) не становятся ссылкой, не показываются гостю и не идут в поиск: «Как добраться» тогда ведёт на поиск Яндекс Карт по месту и тексту адреса. Сервер `address` не разбирает: это текст ≤ 300. Конструктор не сохраняет пункты без названия и места и даёт не больше 8 пунктов.

MediaUrl: `/media/<id>.<ext>` (загруженный файл) или `https://images.unsplash.com/...` (стоковые картинки по умолчанию). `data:`, `blob:` и другие хосты отклоняются с 400.

Срок ответа `rsvpBy` выбирает владелец (шаг «Дата и время» конструктора, не позже даты события). Страница гостя пишет «Пожалуйста, ответьте до …» только если срок задан; выдуманного срока нет. Приём ответов закрыт, когда по календарю Ташкента наступил день после `rsvpBy` или после `date` (в сам день события ответы ещё принимаются, см. 3.6).

Стёртые дата и время: `""` сохраняется как есть и возвращается в `data` (фронтенд не подставляет вместо него значение шаблона); `null` в `PATCH` удаляет ключ. Без даты: страница гостя показывает остальное, `og:title` — только имена, бот и SMS пишут текст без даты, напоминания по расписанию не отправляются (утреннему нужна дата, `r1d` и `r3h` — дата и время), «Напомнить» уходит без даты. Без времени: дата без времени, из напоминаний по расписанию только утреннее. Неверная дата или время — 400 с понятным текстом («Такой даты нет», «Время в формате ЧЧ:ММ»).

### 3.3 Шаблоны

- Сид: 60 строк из `TEMPLATES` в `web/invito-data.js`, `slug = "<event>-<style>"`, `title` = имя шаблона, новые колонки `event`, `style`, `sort_order` (порядок `EVENT_ORDER`, затем стили). Сид идемпотентный (upsert по slug, существующие цены и флаги не трогать). Старый шаблон `invite-cover` выключить (`is_active = false`).
- `GET /api/templates` → `[{ id, slug, event, style, title, price: number|null, smsEnabled }]` (только активные; `price = null` значит общая цена `sharedTemplate`).

### 3.4 Приглашения (нужна сессия)

Объект `Invitation`:
```
{ id, slug, mode: "shared"|"personal", status: "draft"|"active"|"archived", language: Locale,
  template: "<slug>", event, title, data: InvContent, unlocked, paidSeats,
  accessCode: string|null, settings: { r1d, r3h, morning, notify, tables },
  ogImageUrl: string|null, publishedAt, createdAt, updatedAt,
  links: { shared: "<APP_URL>/i/<slug>" | null },
  stats: { guests, yes, no, maybe, pending, replies, people } }
```
`title` сервер берёт из `data.names` (обрезка до 200), отдельно не редактируется. `stats.people` = сумма `1 + plus` по ответившим «да». `settings.tables` = число столов в рассадке (1..30, по умолчанию 4).

- `GET /api/invitations` → `Invitation[]` без архивных, по `updatedAt` убыванию.
- `POST /api/invitations` `{ template, mode?="shared", language, data }` → 201 `Invitation`. Пишет событие `created`.
- `GET /api/invitations/:id` → `Invitation & { guests: Guest[] }`.
- `PATCH /api/invitations/:id` любые из `{ template, mode, language, data, slug, accessCode: string|null, settings }` → `Invitation`.
  - `mode` можно менять, только пока `status = draft`, `unlocked = false` и `paidSeats = 0`, иначе 409.
  - `template`: после оплаты нельзя перейти на шаблон с большей ценой (402), на равный или дешевле можно.
  - `slug`: `^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$`, не из списка зарезервированных (`app`, `admin`, `api`, `media`, `i`, `g`, `health`, `telegram`, `static`, `vendor`), уникальный (409 «Эта ссылка уже занята»).
  - `accessCode`: 1..64 символа или null.
- `DELETE /api/invitations/:id` → 204. Черновик без оплат удаляется, оплаченное или опубликованное переводится в `archived` (публичные страницы отдают 404).
- `POST /api/invitations/:id/duplicate` → 201 новый черновик (данные, шаблон, язык, режим; без slug, оплат, гостей, пароля).
- `POST /api/invitations/:id/publish` → `Invitation` (status `active`, `publishedAt`), либо 402 с текстом, что оплатить. Событие `published` (один раз).
- `PUT /api/invitations/:id/og` (тело `image/png` или `image/jpeg`, ≤ 3 МБ) → `{ ogImageUrl }`. `PATCH`, который меняет нарисованное на превью (имена, дата, время, обложка, шрифт, палитра, шаблон, язык, адрес ссылки, режим), сбрасывает `ogImageUrl` в `null` и удаляет прежнюю картинку: иначе превью показывало бы, например, стёртую дату. До нового `PUT /og` с экрана «Поделиться» `og:image` страницы — обложка.
- `GET /api/invitations/:id/activity?limit=50` → `[{ id, kind, guestId, guestName, meta, createdAt }]`, kind: `created|published|paid|opened|yes|no|maybe|reminder|sms|checkin|test`.
- `POST /api/invitations/:id/bot/test` → `{ ok: true }`, либо 409 «Подключите Telegram, чтобы получать уведомления», если у владельца нет `telegramId`, 503 «Бот сейчас недоступен», если бот выключен, 502 «Не удалось отправить сообщение в Telegram», если Telegram не принял сообщение (например, владелец остановил бота). Если `settings.notify` выключен, сообщение всё равно уходит и говорит об этом. Событие `test`. Лимит 5 в минуту.
- `POST /api/invitations/:id/remind` `{ guestIds? }` → `{ telegram, sms, skipped: [{ guestId, name, reason }], limited }`. По умолчанию все гости без ответа. Только опубликованное приглашение (иначе 400) и оплаченные гости. Сначала Telegram (если гость подключил бота), иначе SMS по правилам раздела 3.5. Одному гостю не чаще раза в 12 часов. `reason`: `seat_unpaid`, `no_channel` (нет Telegram, а SMS недоступны), `no_phone`, `recently_reminded`, `limit_reached` (гостю уже ушли 3 SMS), `invitation_limit`, `rate_limited` (часовой лимит: `limited: true`, отправленные до него засчитаны), `send_failed`. Событие `reminder` с `{ n }`. Лимит 10 в минуту.
- `POST /api/invitations/:id/sms` `{ guestIds? }` → `{ sent, skipped: [{ guestId, name, reason }], limited }`, причины как у `/remind` (кроме `no_channel` и `recently_reminded`). Без `guestIds` уходит только тем, кому приглашение ещё не отправлялось (остальные `already_sent`), с `guestIds` — повторно, в пределах лимитов. Если часовой лимит уже исчерпан, сразу 429.
- Рассылка SMS и напоминаний по одному приглашению идёт по одной: параллельный запрос получает 409 «Рассылка уже идёт, подождите».
- `POST /api/invitations/:id/checkin` `{ token }` → `{ guest: Guest }`. 404, если токен не этого приглашения. Событие `checkin`.

Гость `Guest`:
```
{ id, name, phone, seat, token, link: "<APP_URL>/g/<token>", rsvp: "pending"|"yes"|"no"|"maybe",
  plus, group: "family"|"friends"|"work"|"other", tableNo, checkedIn, checkedInAt, message, messagePublic,
  diet: ("veg"|"halal"|"nonut"|"noalc")[], source: "owner"|"self", openedAt, respondedAt,
  telegramLinked: boolean, paid: boolean, sms: { status, count } | null }
```
- `POST /api/invitations/:id/guests` `{ guests: [{ name, phone?, group?, plus? }] }` (только `personal`) → 201 `Guest[]`. За один запрос 1..500 гостей; больше 500 — 400 «За один раз можно добавить не больше 500 гостей» (на языке `X-Lang`), поэтому большие списки фронтенд шлёт частями по 500.
- `PATCH /api/invitations/:id/guests/:guestId` любые из `{ name, phone, group, plus (0..10), tableNo (0..settings.tables), checkedIn, rsvp }` → `Guest`.
- `DELETE /api/invitations/:id/guests/:guestId` → 204.
- Оплаченность гостя: в режиме `personal` гость оплачен, если его порядковый номер среди текущих гостей (по `seat`) не больше `paidSeats`. Удаление гостя сдвигает следующих в оплаченные. Номера `seat` не переиспользуются (счётчик `invitations.next_seat`). В режиме `shared` все гости оплачены.

### 3.5 SMS

- Приглашение по SMS только для `personal`, опубликованного, оплаченного гостя с телефоном, шаблон с `smsEnabled`.
- Лимит на приглашение: всего не больше `paidSeats × 3` SMS-приглашений и SMS-напоминаний вместе (считаются и SMS удалённых гостей), плюс не больше 3 на гостя (приглашения и напоминания вместе) и 300 в час на пользователя, как сейчас.
- Тексты SMS (`src/sms/texts.ts`): код входа, приглашение и напоминание на ru/uz/uzc/en. В SMS и на страницах гостю видны имена (`data.names`) или название события, но не внутреннее название приглашения.

### 3.6 Публичные страницы

`PublicView`:
```
{ kind: "shared"|"personal", slug, language, template, event, data: InvContent,
  guest?: { name, token, rsvp, count, diet, msg, msgPublic, checkedIn },
  who?: { count, list: [{ name: "Анна К.", plus }], more },
  guestbook?: [{ name: "Анна К.", text }],
  botUsername: string|null, appUrl }
```
- `who` только если `data.showGuests` и секция `who` включена: гости с ответом «да», до 14 имён (имя и первая буква фамилии), `count` = сумма `1 + plus`.
- `guestbook` только если секция `guestbook` включена: до 30 последних сообщений гостей с ответом «да» или «может быть», которые гость сам разрешил показать (`public: true` в ответе, колонка `guests.message_public`). Остальные сообщения видит только владелец (`Guest.message`, `messagePublic: false`); сообщения, оставленные до появления флага, тоже только для владельца.
- `GET /api/public/i/:slug?code=` → `PublicView`. 404, если приглашение не найдено, не опубликовано, не оплачено, в архиве или в режиме `personal`. Если задан пароль и `code` не совпал: 401 `{ locked: true, look: { template, font, palette, language }, error }` (лимит 10 попыток в минуту на IP; `language` — язык приглашения для формы пароля).
- `GET /api/public/g/:token` → `PublicView` с `guest`. 404, если гость не найден, приглашение не опубликовано или место не оплачено. При первом открытии ставит `openedAt` и событие `opened` (запись вне кэша).
- `POST /api/public/i/:slug/rsvp` `{ name (1..80), status, count (1..8), diet, msg (≤ 500), public?, code?, guestToken? }` → `{ guestToken }`. Создаёт или обновляет гостя с `source: "self"`. Лимит 6 в минуту на IP, не больше 1000 таких гостей на приглашение.
- `POST /api/public/g/:token/rsvp` `{ status, count, diet, msg, public? }` → `{ ok: true }`.
- `public` (по умолчанию `false`): показать `msg` в гостевой книге. Повторный ответ без `public` делает сообщение снова личным. Ответ кнопкой в боте сохраняет прежний выбор.
- После срока ответа (`data.rsvpBy`) и после дня события (`data.date`) по Ташкенту оба запроса отвечают 410 «Приём ответов завершён» (не 409: тот означает, что общих ответов слишком много), ответ не меняется; кнопки ответа в боте показывают то же. Страница гостя вместо формы пишет, что приём ответов завершён.
- Ответ гостя: `plus = status === "no" ? 0 : count - 1`, `respondedAt`, событие со статусом, уведомление владельцу в Telegram, если `settings.notify` и у владельца есть `telegramId`.

### 3.7 Файлы

- `POST /api/media` (multipart, поле `file`) → 201 `{ id, url: "/media/<id>.<ext>", kind: "image"|"audio"|"video", mime, size }`. Тип определяется по сигнатуре файла, а не по имени: картинки jpeg/png/webp/gif до 10 МБ, аудио mp3/m4a/ogg/wav до 15 МБ, видео mp4/webm/mov до 50 МБ. SVG и прочее запрещено. Квота 500 МБ на пользователя (кроме админов и бесплатного доступа). Лимит 30 загрузок в минуту.
- `GET /media/<file>` из `MEDIA_DIR` (по умолчанию `./data/media`, в Docker отдельный том): поддержка Range, `Cache-Control: public, max-age=31536000, immutable`, `X-Content-Type-Options: nosniff`.

### 3.8 Текст с помощью ИИ

- `POST /api/ai/write` `{ lang, tone, event, names, host, date, time, venue }` (сессия; 10 в минуту и 50 в сутки на пользователя) → `{ text }`. Без `ANTHROPIC_API_KEY` 503 «Помощник с текстом сейчас недоступен» (клиент берёт готовый текст из дизайна). Запрос к `https://api.anthropic.com/v1/messages` с моделью из `AI_MODEL` (по умолчанию `claude-opus-5-5`), `max_tokens` 400, тот же промпт, что в `aiWrite` дизайна.
- Поля: `lang` — Locale, `tone` — `warm|formal|playful|poetic|short`, `event` — ключ `EVENTS`, `names`/`host`/`venue` — строки до 200 символов (переводы строк заменяются пробелами), `date` — `YYYY-MM-DD` или пусто, `time` — `HH:MM` или пусто; лишние поля дают 400. Превышение лимитов — 429, ошибка или отказ модели — 502 «Помощник не смог написать текст, попробуйте ещё раз».

### 3.9 Заказы

`POST /api/orders`, `GET /api/orders` (заказы этого пользователя, новые сверху, не больше 100: история платежей в профиле), `GET /api/orders/:id`. Заказ в ответах: `{ id, number, kind, invitationId, quantity, amount, currency, status, checkoutUrl, paidAt, createdAt }` (без `meta`: уведомление платёжной системы клиенту не отдаётся и хранится без токена карты и подписи). Тестовая оплата: `/app/#/mock-pay/<id>`.
- Возврат после оплаты: `POST /api/orders` принимает необязательное `returnTo: "app" | "telegram"`. `app` — `/app/#/orders/<id>` (экран заказа, нужна сессия). `telegram` — `/app/#/paid/<id>`: оплату из мини-аппа Telegram открывает во внешнем браузере без сессии, поэтому этот экран не требует входа и без сессии не запрашивает заказ. С сессией он сразу переходит на `#/orders/<id>`, без неё показывает короткую карточку в стиле Invito «Оплата завершена — вернитесь в Telegram» с кнопкой `https://t.me/<botUsername>` (из `/api/auth/config`; без бота кнопки нет) и без данных заказа. Заказ мини-аппа отмечается оплаченным по колбэку Multicard, мини-апп узнаёт об этом сам, опрашивая `GET /api/orders/:id`. Без `returnTo` сервер выбирает `telegram`, когда запрос пришёл с `Authorization: Bearer` (так входит мини-апп), иначе `app`. Мини-апп шлёт `returnTo: "telegram"` при `tgReal`.
- Бесплатный заказ → 200 `{ status: "fulfilled", order: null, message }`, `message` на языке запроса (`X-Lang`). Начатые оплаты шаблона при этом отменяются.
- Подписка (`{ kind: "subscription", months: 1–12 }`) пользователю с бесплатным доступом или администратору не продаётся: 400 «У вас бесплатный доступ: подписка не нужна» (на языке запроса). Экран цен такому пользователю кнопок подписки не показывает.
- Повторно оплаченный счёт за уже открытый шаблон отклоняется в колбэке («Шаблон уже оплачен»), заказ получает `cancelled`: Multicard отменяет такую оплату.

### 3.10 Реквизиты для юридических страниц (админка)

`Legal`: `{ companyName, inn, address, phone, email, telegram, bankName, bankAccount, mfo, director }`, все поля — строки, пустая строка значит «не задано». Хранится в таблице `settings` под ключом `legal` (`getLegal`/`setLegal` в `src/services/settings.ts`, кэш 5 минут сбрасывается при сохранении, как у цен); запись, которая не проходит схему, считается пустой.
- `GET /api/admin/legal` (админ) → `Legal`.
- `PUT /api/admin/legal` (админ) `Legal` → сохранённый `Legal`. Заменяет все поля: не присланные становятся пустыми, лишние поля и не строки — 400 «Неверные данные». Пробелы и переводы строк схлопываются, края обрезаются. Длина: `companyName`, `bankName`, `director` ≤ 200, `address` ≤ 300, `phone` ≤ 40, `email` ≤ 120, `telegram` ≤ 64, `inn` и `mfo` ≤ 20, `bankAccount` ≤ 40. `email` — адрес или пусто, иначе 400 «Email: адрес вида name@example.com». `telegram` принимает `@name`, `name` или `https://t.me/name` и хранится как `name` (5–32 символа: латиница, цифры, `_`, первая — буква), иначе 400 «Telegram: имя пользователя, например @invito_support».
- В админке — вкладка «Реквизиты» (`#/legal`) со ссылками на три страницы.

## 4. Фронтенд: что меняется в логике Invito

Принцип: внешний вид и анимации дизайна сохраняются. Новые экраны и листы (вход, оплата, аккаунт, добавление гостей) рисуются в той же системе: цвета `ui()`, шрифты Onest/Cormorant, акцент `#d4452a`, нижние листы как `sheet`/`importOpen`, тосты.

1. Загрузка. Прочитать `#invito-boot`. Режим `app`: обычное приложение. `shared`/`personal`: сразу `screen: 'guest'`, `guestMode: 'live'`, данные из `view` (без шапки и переходов в конструктор, кроме кнопки «Создать своё» в подвале, ведущей на `/app/`). `notfound`: экран «Приглашение не найдено» в стиле дизайна. Язык интерфейса: из профиля (`/api/auth/me`), иначе из `localStorage`, иначе из `Telegram.WebApp.initDataUnsafe.user.language_code` или `navigator.language`, иначе `ru`.
2. Telegram. `tgReal` (настоящий Telegram) включает раскладку `tg` без поддельной шапки и поддельной MainButton (они только для симуляции в туре). Вход через `POST /api/auth/webapp`, полученный `token` идёт в `Authorization: Bearer` каждого запроса (`invito-api.js`); при `phone_required` лист сначала объясняет, зачем номер («{имя}, остался один шаг»), и вызывает `Telegram.WebApp.requestContact` только по нажатию «Поделиться номером»; опрос `/webapp` не чаще, чем позволяет лимит маршрута (до нажатия — раз в 15 с), отказ и ошибка бота — обычным текстом в листе, «Позже» закрывает лист. Ссылки t.me открывать через `openTelegramLink`, внешние (оплата) через `openLink`. В мини-аппе «Выйти» нет (вход — аккаунт Telegram, выход тут же вернул бы его же): вместо кнопки — пояснение. «Админка» из мини-аппа открывается во внешнем браузере по одноразовой ссылке входа `POST /api/auth/handoff` (запрашивается при открытии профиля).
3. Шапка, вход и профиль. Шапка: логотип; на широком экране разделы «Шаблоны», «Цены» (`#/pricing`), «Мои приглашения», «Возможности», на телефоне они в меню (☰); кнопка языка интерфейса (код языка ▾, меню с полными названиями, см. п. 5); без входа — «Войти», с входом — круг с инициалами. «Войти» сразу открывает лист входа, круг — профиль; на экране от 720 px оба — окна по центру, на телефоне — листы снизу.
   Лист входа на сайте: при боте (`/api/auth/config` → `telegram: true`) первым — «Войти через Telegram»: ссылка на бота заготавливается при открытии листа (`/telegram/start`, обновляется, пока лист открыт), поэтому кнопка — обычная ссылка t.me (на сенсорном экране — в этой же вкладке, на компьютере — в новой). После нажатия — шаги в Telegram («Запустить», «Поделиться номером» один раз, «Подтвердить вход»), обратный отсчёт срока ссылки, на компьютере ещё QR той же ссылки, опрос `/telegram/poll` раз в 2 с и сразу при возврате на страницу. Запрос (`nonce`, ссылка, срок, действие) хранится в `localStorage` (`invito.tglogin`): после ухода на t.me и перезагрузки ожидание продолжается тем же запросом. Вторым — вход по номеру: подсказка формата, код с отсчётом «Новый код через N с», «Изменить номер» (тот же номер в течение минуты не запрашивается снова — сразу поле кода), ошибки сервера в листе; при сбое SMS — совет войти через Telegram. Поле номера получает фокус, только если бота нет.
   Вход нужен для «Использовать шаблон» (создание черновика), «Мои приглашения», публикации, гостей, оплаты; лист тогда говорит, зачем вход и что после него продолжится, а действие продолжается после входа (для шаблона и «Моих приглашений» — и после перезагрузки страницы). Просмотр главной, тура, событий, шаблонов, цен и превью без входа.
   Главная: что такое Invito — онлайн-приглашение, которое отправляют ссылкой в Telegram или WhatsApp, гости отвечают в нём, а личные приглашения — с именем гостя. Порядок: «Мои приглашения» (вверху, если вошли и приглашения есть; иначе раздел ниже вопросов с подсказкой войти или «Создать приглашение»), первый экран (подпись, заголовок, описание, строка цен, «Создать приглашение» → выбор события, «Смотреть шаблоны» → все шаблоны тура, три коротких преимущества), витрина шаблонов (название стиля на языке интерфейса, событие и цена; нажатие открывает шаблон на экране шаблонов), «Как это работает» (4 шага), «Что увидят гости» (6 карточек и «Все возможности» → тур), «Цены» (общая ссылка «от» самой низкой цены шаблона, место гостя, подписка в месяц — только из `/api/auth/config`, `/api/auth/me` и `GET /api/templates`, пока их нет — «Загрузка»; бесплатный доступ и подписка отмечены; «Все цены и подписка» → `#/pricing`), вопросы и ответы (7, раскрываются по одному), последний призыв и подвал: разделы, «Публичная оферта» `/oferta`, «Политика конфиденциальности» `/privacy`, «Контакты» `/contacts` (на языке интерфейса: `?lang=uz|uzc|en`, у русского без него; новая вкладка, в мини-аппе — `openLink`), бот `https://t.me/<botUsername>`, если он настроен, светлая/тёмная тема (не в мини-аппе).
   Профиль: имя (правка имени и фамилии → `PATCH /api/auth/me`, после неё Telegram имя не меняет), номер, «Мои приглашения», подписка (статус с датой окончания, «Оформить подписку» или «Продлить подписку» → `#/pricing`), Telegram (подключён с @username или «Подключить Telegram» — тот же вход через бота), история платежей (`GET /api/orders`: дата, что оплачено, сумма, статус), язык интерфейса, админка для админов, «Выйти». Выход и вход другим человеком сбрасывают всё, что относится к аккаунту: открытое приглашение, гостей, адрес и пароль ссылки, листы оплаты и заказа.
4. Черновики на сервере. «Использовать шаблон» → `POST /api/invitations`. Автосохранение → `PATCH` только с изменёнными ключами `data` (сервер сливает `data` по ключам, поэтому правки из другой вкладки в остальных полях не затираются; дебаунс как в дизайне, индикатор «Сохранено · HH:MM» по ответу сервера). Ошибки 4xx, кроме 429, не повторяются по таймеру, 428 открывает шаг телефона. Смена шаблона в конструкторе или редакторе → `PATCH template`. «Мои приглашения» из `GET /api/invitations` (без примеров-заглушек, пустое состояние с кнопкой «Создать»); дублирование, удаление (с подтверждением), открытие, гости; открытие и гости — по свежему `GET /api/invitations/:id`. На главной — первые три карточки и «Показать все · N». Главная кнопка карточки: у опубликованного — «Поделиться» (экран ссылки), у черновика — «Опубликовать» (лист публикации и оплаты, как «Получить ссылку») и подсказка, что гости его пока не видят. «Изменить»: опубликованное открывается сразу в редакторе на странице приглашения, черновик — в конструкторе на шаге, где его оставили (номер шага хранится в `localStorage` под `invito.step.<id>`). Название шаблона в карточке — название стиля на языке интерфейса. Выбор события, шаблона или демо из тура сбрасывает `draftId`, чтобы не перезаписать открытый черновик.
5. Языки. Переключатель интерфейса — кнопка в шапке на всех экранах с шапкой (телефон, компьютер, мини-апп): меню «Русский, O‘zbekcha, Ўзбекча, English» с отметкой текущего; выбор сохраняется в профиль (`PATCH /api/auth/me`) или, без входа, в `localStorage`. Язык приглашения отдельно: выбор в шаге «Основное» конструктора и в редакторе, хранится в `invitation.language`, тексты по умолчанию берутся на этом языке, пока пользователь их не правил. Страница гостя показывается на языке приглашения; кнопка языка у гостя меняет только его просмотр.
6. Файлы. Обложка, галерея, видео и аудио загружаются через `POST /api/media` (картинки перед загрузкой уменьшаются до 2000 px по длинной стороне, JPEG 0.85), в `data` попадает URL. Пока идёт загрузка, показывать прогресс; ошибки тостом.
7. Публикация и оплата. «Получить ссылку» для неопубликованного приглашения открывает лист публикации: выбор «Одна ссылка для всех» (цена шаблона или бесплатно по подписке и бесплатному доступу) или «Личные приглашения» (N гостей × цена места; подписка мест не оплачивает). Карточка подписки — только у общей ссылки с неоплаченным шаблоном (и в листе «шаблон дороже оплаченного»): сроки 1, 3, 6 и 12 месяцев (любые шаблоны без оплаты, места отдельно) и «Подробнее о подписке» → `#/pricing` (назад — снова лист с тем же выбором). «Докупить места» — тот же лист без выбора типа: сколько мест докупить, сколько оплачено и сколько гостей без места. В мини-аппе оплату из листа запускает MainButton Telegram, своей кнопки в листе нет. Под «Оплатить …» (когда есть что оплатить), под кнопкой подписки в листе и под сроками на экране цен — строка согласия «Нажимая «Оплатить» (или «Оформить» / «Продлить»), вы принимаете условия оферты» со ссылкой на `/oferta` на языке интерфейса (`payConsent`, `consentLink`, `payWord` в словаре). Оплата → `POST /api/orders` → если `fulfilled`, сразу публикация; иначе переход на `checkoutUrl` и возврат на `/app/#/orders/<id>` с опросом статуса и продолжением после оплаты (в Telegram оплата открывается через `openLink`, возврат во внешнем браузере на `/app/#/paid/<id>`, а мини-апп опрашивает заказ сам, см. 3.9). Что делать после оплаты (приглашение, публиковать ли, куда вернуться), хранится в `localStorage` (`invito.order.<id>`): сайт уходит на страницу оплаты целиком. До ухода кнопки покупки заняты («Переходим к оплате…»), повторное нажатие второго заказа не создаёт; возврат кнопкой «Назад» браузера их освобождает. Экран тестовой оплаты `#/mock-pay/<id>`.
   Экран заказа: что оплачивается (имена и шаблон приглашения, срок подписки, число мест), «Открыть страницу оплаты» (и на сайте), через 20 с ожидания — «Изменить заказ» (снова лист оплаты). Опрос: 2 с, после минуты — 5 с, после 5 минут — 15 с; через 30 минут он останавливается, кнопка «Проверить снова» запускает его заново. Отказ — «Попробовать снова»: новый заказ того же (подписка — снова экран цен с тем же сроком, покупка шаблона — сразу оплата того же черновика). Подписка без приглашения после оплаты возвращает на экран цен, а не на главную.
   Экран цен `#/pricing` (раздел «Цены» в шапке, ссылки из профиля, листа оплаты и карусели шаблонов; без входа тоже). Разовая оплата: общая ссылка «от» самой низкой цены шаблона (своя `price` шаблона из `GET /api/templates`, иначе `prices.sharedTemplate`) и место гостя (`prices.seat`). Подписка: что входит (все шаблоны для общих ссылок, публикация без оплаты шаблона) и что нет (места персональных ссылок), сроки 1/3/6/12 месяцев по `prices.subscriptionMonth` × месяцы с ценой в месяц и датой окончания. «Оформить» → вход при необходимости → `POST /api/orders { kind: "subscription", months }` → оплата → снова `#/pricing` с сообщением «Подписка оформлена» и обновлённым статусом (`/api/auth/me`). Статус: «У вас бесплатный доступ» (кнопок подписки нет), «Подписка до <дата>» с «Продлить» (срок прибавляется к концу текущей), без подписки — ничего. Короткие вопросы и ответы. В мини-аппе — BackButton (назад, откуда пришли) и MainButton «Оформить» выбранного срока.
   «Купить шаблон» в карусели шаблонов и в превью: цена текущего шаблона («50 000 сум», «Входит в подписку», «Бесплатно для вас»). Покупка → вход при необходимости → черновик с этим шаблоном (общая ссылка) → `POST /api/orders { kind: "template", invitationId }` → оплата → снова конструктор этого черновика (он не публикуется) и тост «Шаблон оплачен»; «Получить ссылку» потом публикует без оплаты. С подпиской и бесплатным доступом кнопка просто открывает конструктор, в превью её нет.
8. Экран «Поделиться». Ссылка `appUrl/i/<slug>` (без домена invito.app). Редактирование slug → `PATCH slug` (дебаунс, ошибка занятости). Пароль → `PATCH accessCode`. QR генерируется локально (`qrcode-generator`), без api.qrserver.com. OG-картинка из `renderCard` после генерации загружается `PUT /og`. Блок мета-тегов показывает настоящие URL. Для `personal`: список личных ссылок гостей (`guest.link`), отметка неоплаченных, кнопка «Докупить места».
9. Страница гостя. Данные из `PublicView`: поля, которых в нём нет (дата, программа, контакты, дресс-код, галерея), не подставляются из шаблона, их блоки скрыты. Дата и время события — по Ташкенту (UTC+5) и в календаре, и в обратном отсчёте; узбекские даты — из таблиц `UZ_DATES` в том же виде, что у сервера. Личная: «{имя}, вы приглашены», конверт «Кому», ответ предзаполнен, после ответа «да» показывается QR для отметки на входе (кодирует `guest.link`). Общая: ответ с именем → `POST /rsvp`, `guestToken` хранится в `localStorage` по slug, чтобы можно было изменить ответ. Пароль проверяет сервер (`?code=`). «Кто придёт» и гостевая книга из `who`/`guestbook`. «Ответить через бота» → `https://t.me/<botUsername>?start=g_<token>` (скрыть без бота). Музыка, интро, карта, календарь как в дизайне.
10. Гости (`manage`). Список из `GET /api/invitations/:id`. «Импорт из Telegram» заменяется листом «Добавить гостей»: одна строка на гостя «Имя, телефон» плюс быстрая форма. Группа, стол, отметка входа, удаление → `PATCH`/`DELETE`. «Напомнить» → `POST /remind`. Отправка приглашений по SMS (одному и всем) с статусом SMS у гостя; «SMS всем» и «Напомнить» — после подтверждения с числом получателей. CSV с телефонами; значения, похожие на формулу (`=`, `+`, `-`, `@` в начале), начинаются с апострофа. Рассадка с числом столов из `settings.tables` (кнопки +/-). Отметка входа камерой: QR с `/g/<token>` → `POST /checkin`. Вкладка «Активность» из `/activity`. Вкладка «Бот»: переключатели → `PATCH settings`, «Тест» → `POST /bot/test`, лента из активности, подсказка подключить Telegram.
11. Тур. Остаётся витриной: демо работают в демо-режиме (`state.demo`) на данных `GUESTS` из `invito-data.js`, без запросов к API и без записи в черновики. Видимая метка «Демо». Две вкладки: «Возможности» (демо по разделам «Открытие», «Для гостей», «Оформление», «Отправка», «Организатору», описания без технических слов) и «Все шаблоны» (фильтры по событию и стилю, цена шаблона). Переключателей языка, Telegram и тёмной темы в туре нет: язык — в шапке, тема — в подвале главной. В мини-аппе своей кнопки «Назад» на экранах тура, событий и шаблонов нет — BackButton Telegram.
   События: под названием — сколько активных шаблонов у события (по `GET /api/templates`, выключенные в админке не считаются) и цена («от», если цены разные). Экран шаблонов: название стиля и описание на языке интерфейса, вместо списка шрифтов — что можно настроить (текст и программа; фото, музыка и открытие; число вариантов цвета и шрифтов), названия цветов на языке интерфейса; на экране от 720 px — стрелки по бокам карусели, точки и «2 из 5», на телефоне — точки и «1 из 5 · листайте →». В мини-аппе под каруселью кнопка «Предпросмотр»; в предпросмотре «Назад» и «Выбрать шаблон» лежат над заставкой (конвертом, занавесом), а не под ней.
12. ИИ. `aiWrite` вызывает `POST /api/ai/write`, при 503 или ошибке берёт готовые тексты дизайна (как сейчас при отсутствии `window.claude`).
13. Ошибки и пустые состояния: сеть, 401 (снова вход), 402 (лист оплаты), 404, 409, 429 показываются тостом на языке интерфейса. Красная плашка рантайма `.sc-logic-error` скрыта CSS в оболочке; ошибки пишутся в консоль.
14. Убрать заглушки прототипа: примеры приглашений на главной, фальшивую активность, `CONTACTS`, фальшивые пожелания `msgIdx` (кроме демо-режима).

## 5. Бот

- `/start g_<token>` (гость открыл бота со страницы приглашения): после обязательного телефона (ожидающий payload хранится в Redis, пока человек делится контактом) бот привязывает чат к гостю (`guests.telegram_chat_id`), присылает карточку приглашения с кнопкой открыть (`/g/<token>`) и кнопками ответа «Приду / Возможно / Не приду». Ответ через кнопки идёт тем же путём, что `POST /api/public/g/:token/rsvp`.
- Уведомления владельцу (`settings.notify`): ответ гостя, отметка на входе. Через интерфейс `ctx.notifier` (`sendToUser(userId, text, opts)` и `sendToChat(chatId, text, opts)`, `opts.buttons` — кнопки-ссылки), который реализует бот; без бота это no-op. Тексты на языке профиля владельца (`src/services/notify.ts`), ошибки Telegram только пишутся в лог.
- Напоминания гостям в Telegram по `settings.r1d` (за сутки), `r3h` (за 3 часа), `morning` (в 9:00 по Ташкенту в день события): задача раз в минуту, гости с привязанным чатом и ответом «да», «может быть» или без ответа, учёт отправленных в таблице `guest_reminders (guest_id, kind)` с уникальным ключом, отправка только если вставка прошла.
- Язык бота: добавить `uzc` в меню `/lang`. Тексты бота для `uzc` через `toCyr`.
- Вход и подключение Telegram с сайта (`/start auth_<nonce>`, раздел 3.1): оба требуют номер в боте. Telegram без номера бот просит поделиться контактом (при подключении — текстом о том, что номер должен совпасть с номером аккаунта), а запрос ждёт контакта и после него продолжается. Подключение проходит, только если Telegram после контакта — это аккаунт запроса (тот же номер), иначе запрос сразу завершается отказом с причиной для сайта. Подтверждение подключения показывает номер аккаунта со скрытой серединой и устройство. Номер контакта — международный (`contactPhone`): узбекский только `998` и 9 цифр, остальные хранятся цифрами (7–15), девять цифр не дополняются до +998. Отказ принять контакт (номер у другого Telegram, чужой контакт, нераспознанный номер) бот запоминает для мини-аппа (`error` в `phone_required`).
- Даты в боте — по календарю Ташкента, как в приложении: «Ваша подписка активна до 20 мая 2031 г.» для подписки до 19 мая 20:30 UTC. Подстановка, которая сама кончается точкой (русская дата «… г.»), перед точкой текста не даёт двух точек подряд.

## 6. Найденные проблемы бэкенда, которые нужно исправить

Список с шагами воспроизведения ведётся вне репозитория (он публичный). Для старых страниц `public/app` (заменяются дизайном) исправления переносятся в новый фронтенд: опрос `/webapp` медленнее лимита, `initData` важнее старой сессии в мини-аппе, понятная ошибка вместо пустой страницы.
