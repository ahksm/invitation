# InviteBloom

Платформа приглашений по шаблонам: кабинет пользователя, Telegram-бот и мини-апп, оплата через Multicard, SMS через Eskiz и админка владельца. Сайт — [invitebloom.tech](https://invitebloom.tech), бот — [@invitebloombot](https://t.me/invitebloombot).

Название продукта — InviteBloom: на сервере это постоянная `BRAND` в `src/brand.ts` (заголовки и мета-теги страниц, юридические страницы, кнопка мини-аппа в боте, SMS с кодом входа), в интерфейсе — тексты `web/`. Из окружения название не берётся: строка `APP_NAME` в старом `.env` ни на что не влияет. Дизайн пришёл из проекта Claude Design «Invito»; это имя осталось только во внутренних именах (файлы `web/Invito.dc.html` и `invito-*.js`, ключи `localStorage` `invito.*`, `#invito-boot`), которые пользователь не видит.

## Что умеет

- **Вход** по номеру телефона с кодом из SMS или через Telegram (кнопка на сайте, бот, мини-апп). Номер телефона обязателен: при входе через Telegram бот просит поделиться контактом. Telegram с тем же номером можно подключить к аккаунту, созданному по номеру («Подключить Telegram» в аккаунте).
- **Приглашения**: общее (одна ссылка для всех) или персональное (своя ссылка каждому гостю), ответы гостей «приду / не смогу».
- **SMS гостям** со ссылкой на персональное приглашение, если для шаблона включены SMS.
- **Языки**: интерфейс и каждое приглашение на русском, узбекском или английском.
- **Тарифы**:
  - бесплатный доступ, выданный владельцем: всё бесплатно;
  - общий шаблон: оплата за шаблон;
  - персональные приглашения: оплата за каждого гостя;
  - подписка: любые шаблоны без оплаты, места гостей оплачиваются отдельно.
- **Админка** (`/admin/`): кто пользовался платформой, приглашения и платежи каждого, журнал действий и SMS, выдача бесплатного доступа и блокировка, цены, шаблоны.

## Стек

Node.js 22, TypeScript, Fastify, PostgreSQL (Drizzle ORM), Redis (кэш, лимиты, коды входа), grammY (бот).

## Запуск

```bash
cp .env.example .env   # заполнить
docker compose up --build
```

Локально без Docker нужны PostgreSQL и Redis:

```bash
npm install
npm run db:migrate
npm run dev            # http://localhost:3000
npm test               # нужна база invite_test, см. test/api.test.ts
npm run test:e2e       # проверка фронтенда в Chromium, см. «Фронтенд»
```

Миграции и каталог из 60 шаблонов дизайна (12 событий × 5 стилей) применяются и при старте сервера; сид идемпотентный, цены и флаги шаблонов, заданные в админке, сохраняются. После изменения `src/db/schema.ts` выполните `npm run db:generate`.

Для разработки удобно `PAYMENT_PROVIDER=mock` и `SMS_PROVIDER=mock`: оплата проходит на тестовой странице, а SMS (в том числе коды входа) пишутся в лог. В production эти режимы запрещены.

## Фронтенд

Интерфейс (приложение, мини-апп и страницы гостей `/i/<slug>`, `/g/<token>`) — дизайн из Claude Design. Его исходники лежат в `web/` как есть:

- `Invito.dc.html` — всё приложение, `InviteCover.dc.html` — обложка шаблона;
- `invito-data.js`, `invito-engine.js`, `invito-api.js` — ES-модули, которые подгружает логика;
- `support.js` — рантайм `.dc.html` из Claude Design. **Руками не правится.**

Сервер при старте собирает фронтенд в памяти (`src/web/`): `/app/dc-bundle.js` с шаблонами и логикой всех `.dc.html`, `/app/support.js` — оригинальный рантайм с патчами из `src/web/support-patches.ts` (логика без `eval`, React из `node_modules` вместо unpkg, без повторной загрузки страницы и `postMessage`). Каждый патч ищет точный фрагмент `web/support.js`; если фрагмента нет, сервер не запустится с понятной ошибкой. Так же сервер не запустится, если в логике какого-нибудь `.dc.html` синтаксическая ошибка (в сообщении файл и строка): логика всех DC идёт одним скриптом, и в браузере такая ошибка дала бы пустую страницу. Файлы под `/app/` сжимаются (br, gzip) один раз при сборке. Все страницы отдаёт одна оболочка с загрузочными данными в `#invito-boot`; страницы `/i/<slug>` и `/g/<token>` получают данные приглашения, мета-теги для превью и 404 от `getPublicPage` (подключается в `src/app.ts`) и закрыты от индексации (`noindex`). В development сборка обновляется при изменении файлов в `web/`.

Как обновить дизайн из Claude Design:

1. Заменить файлы в `web/` новыми (`support.js` тоже кладётся как есть, без правок).
2. В `Invito.dc.html` повторить две правки, без которых сервер не стартует: убрать из `<helmet>` `<script src="https://telegram.org/js/telegram-web-app.js">` (его подключает оболочка) и заменить `import(new URL('./invito-data.js', base).href)` на `import('/app/invito-data.js')` (так же для остальных модулей), иначе страницы `/i/…` и `/g/…` ищут модули не там.
3. Если сервер сообщает, что патч не применился, сверить `src/web/support-patches.ts` с новым `support.js`.
4. Проверить: `npm test` и `npm run test:e2e`. Браузер для e2e — `PLAYWRIGHT_CHROMIUM`, `/opt/pw-browsers/chromium` или `npx playwright-core install chromium`; с `E2E_SHOTS_DIR=<папка>` тест сохраняет скриншоты.

## Безопасность

- Ключи только в `.env` или секретах хостинга, в репозиторий они не попадают.
- Сессия в httpOnly-cookie, изменяющие запросы принимаются только со своего домена. Токен сессии в ответе получает только мини-апп (вход по initData и, по флагу `bearer`, вход по SMS и через бота внутри Telegram): во фрейме Telegram Web cookie не доходит.
- «Подключить Telegram» подключает только Telegram, который подтвердил номер аккаунта своим контактом в боте: пересланная или подсмотренная ссылка подключения не даст подключить к аккаунту чужой Telegram и входить им. Telegram с другим номером или другого аккаунта не подключается, не объединяется с аккаунтом и не переключает сессию. Номер из контакта Telegram — международный: девять цифр не считаются узбекским номером без +998.
- CSP без `unsafe-eval` и сторонних CDN. Страницы приложения разрешают встраивание только Telegram (мини-апп в Telegram Web), админку встраивать нельзя.
- Лимиты запросов в Redis: общий, на вход, на коды SMS (раз в минуту и 5 в час на номер), на рассылку SMS (3 на гостя, paidSeats × 3 на приглашение, 300 в час на пользователя), на помощника с текстом.
- IP клиента берётся из X-Forwarded-For только от доверенных прокси: `TRUST_PROXY` — их число или адреса.
- Код из SMS хранится в виде HMAC, сгорает после 5 неверных попыток.
- Вход через Telegram: сессию получает только браузер, начавший вход; вход подтверждается кнопкой в боте.
- Подписи проверяются у мини-аппа Telegram, вебхука бота (secret token) и колбэков Multicard; колбэк Eskiz защищён секретом в адресе.
- Повторный колбэк об оплате ничего не начисляет дважды, сумма сверяется с заказом. Из уведомления об оплате не сохраняются токен карты и подпись, а клиент получает заказ без служебных полей.
- В лог запросов адреса пишутся без секретов: пароль приглашения (`?code=`), одноразовый код входа и секрет колбэка SMS заменяются на `***`.

## Перед запуском в бой

1. **Multicard**: получить ИКПУ и код упаковки услуги на tasnif.soliq.uz и указать их в `MULTICARD_MXIK` и `MULTICARD_PACKAGE_CODE` (без них счёт не создаётся), при необходимости `MULTICARD_VAT`. Боевой адрес `https://mesh.multicard.uz`. Колбэк приходит на `https://<домен>/api/payments/multicard/callback`; ответ не 200 отменяет оплату, поэтому отказ даётся только при неверной подписи, неизвестном заказе, несовпадении суммы или повторной оплате уже открытого шаблона.
2. **Eskiz**: отправить на модерацию тексты SMS из `src/sms/texts.ts` (12 шаблонов: код входа, приглашение и напоминание на четырёх языках), задать `SMS_CALLBACK_SECRET`. Текст с кодом входа называет сайт (домен из `APP_URL`): иначе Eskiz отказывает по пункту 2 своей инструкции. Пока текст кода на языке человека не одобрен и Eskiz отвечает отказом, код уходит текстом на узбекской латинице. Тестовый аккаунт Eskiz отправляет только фразу «This is test from Eskiz»: для разработки есть `ESKIZ_TEST_MODE=true`, тогда настоящий текст с кодом пишется в лог.
3. **Telegram**: создать бота в @BotFather, указать `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_MODE=webhook` и `TELEGRAM_WEBHOOK_SECRET`. Кнопка мини-аппа («InviteBloom») ставится автоматически, если `APP_URL` начинается с https.
4. Указать себя в `ADMIN_PHONES` или `ADMIN_TELEGRAM_IDS`. Права админа пересчитываются по этим спискам при каждом запросе.
5. Сайт работает только по https за прокси (nginx): `APP_URL` — публичный https-адрес, в production другой не принимается (без https CSP переводит скрипты на https и страница пустая, а запросы с другого адреса отклоняются проверкой Origin). Задать `TRUST_PROXY=1` (или адреса прокси) и закрыть порт приложения от прямого доступа: иначе `X-Forwarded-For` подделывается и лимиты по IP (в том числе на SMS с кодом) не работают. `docker-compose.yml` публикует порт только на `127.0.0.1:3000`, для nginx на этом же сервере; не меняйте это на `3000:3000`: порты, опубликованные Docker, ufw не закрывает.

## Устройство

```
src/
  app.ts            Fastify: защита, сессии, маршруты
  server.ts         запуск API и бота
  brand.ts          название продукта (InviteBloom)
  pricing.ts        правила оплаты
  i18n.ts           языки, переводы ошибок и текстов бота
  auth/             вход через Telegram и одноразовые ссылки
  bot/              Telegram-бот
  payments/         Multicard и тестовый провайдер
  sms/              Eskiz, тестовый провайдер, тексты SMS
  services/         пользователи, приглашения, заказы, телефоны, SMS
  routes/           HTTP API
  web/              сборка фронтенда из дизайна, оболочка страниц, CSP
web/                исходники дизайна из Claude Design (см. «Фронтенд»)
public/
  admin/            админка
  shared/           общие файлы админки
```
